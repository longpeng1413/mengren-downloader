## v0.5.0 新增：QQ 音乐单曲下载（2026-10-14）

用户要求增加 QQ 音乐并选定方案：先直接下载，读不到再用专用 Edge；第一版只做单曲；保存 .lrc 歌词。用户有 QQ 音乐会员，已在本机专用 Edge 自行登录供实测。

- 调研结论：yt-dlp 自带 qqmusic，但会员歌要求导出 Cookie，违反项目约定，因此不用 Cookie 方案；第三方解析网站、解密客户端加密文件（mflac/mgg 等）均不采用。
- 官方接口 `u.y.qq.com/cgi-bin/musicu.fcg`：歌曲信息、vkey 地址、歌词。实测**设备编号 guid 必须随机**，固定值返回 code 1000、无地址（早期“网页内调用失败”误判即此原因）。网页版播放器未登录不再播放；网页内用 `credentials:'include'` 调同一接口可行，登录由浏览器带上，无需也不读取 QQ 号/Cookie。
- `source/qqmusic.mjs`：链接解析（songDetail、ryqq_v2、yqq 旧页、手机 playsong、c6.y.qq.com 短链仅在 y.qq.com 内跟随跳转）；普通音质直连接口（无 Cookie）；最高音质在专用 Edge 的歌曲页内调用，未登录时提示扫码并等待；按 FLAC > 320k > 128k > 96k M4A > 48k M4A 选择账号被授予的地址，带 ekey（加密）的格式跳过；音频服务器只允许 `*.stream.qqmusic.qq.com` 下这几种文件名。
- 下载：服务器对每条连接限速约 200KB/s（接近播放速度），改为 4 连接 × 1MiB 分段，经中继同样的域名/公网 IP/跳转检查，逐段核对 Content-Range 和长度，失败段最多重试 3 次。完整解码校验，解码时长短于整首（容差 max(3 秒, 2%)）视为试听片段拒绝保存；写入歌名/歌手/专辑标签（-c copy，不转码），文件名“歌名 - 歌手.ext”，同名追加 (2)；.lrc 为带 BOM 的 UTF-8，不覆盖已有文件。
- 实测（本机）：免费歌 004Ti8rT003TaZ 普通音质 128k MP3，4,501,182 字节，4:41.29 整首解码通过，标签和歌词正确。会员歌《晴天》0039MnYb0qxYhV 最高音质：账号返回 FLAC/320k/128k/96k/48k 全部可用，下载 24 位无损 FLAC 55,396,564 字节，4:29.75；单连接 270 秒，分段后整次会话 85 秒，两次下载文件哈希一致；同名第二次保存为 (2)。普通音质遇会员歌自动转专用 Edge 成功。成功后本次打开的 Edge 标签已关闭。
- 已知：该 FLAC 在 4:27.6 附近有 1 个 FLAC 帧解码报错；不经任何处理直接下载的原始文件同样如此，标签前后解码音频 MD5 一致，判断为 QQ 音乐源文件本身问题，软件按“整首时长正确”保存。
- 回归：新增 6 项（链接/域名、格式选择与加密跳过、网页内读取不碰 Cookie/存储、歌词与文件名/同名、试听片段拒绝、分段下载拼接/重试/错位拒绝），全套 41 项通过。
- 2026-10-14 用户补充：要给老人机内存卡下歌，最高音质（FLAC）老人机可能不认，要求列出音质自选。改为读取后列出全部可下音质、大小和兼容提示，回车默认最高的 MP3，只下所选格式；分段由 4MiB 改为 1MiB，128k 小文件实测 210→835KiB/s。实测“看到提示再输入”选 3 下载《晴天》128k MP3（4,317,204 字节，4:29.79，44.1kHz 立体声，ID3v2.3，无内嵌封面）。新增菜单/默认/重问回归，全套 42 项通过。未在老人机实物上播放验证。
- 未验证：非会员账号读会员歌的提示、数字专辑/单曲付费歌、App 分享短链的真实跳转（只有格式测试）、songid 形式链接的真实接口、另一台电脑；歌单/专辑未实现。

- 用户明确要求先完成功能和下载包，在自己的笔记本登录大号微信测试咖米课程。开发本机不激活真实系统代理、不安装抓取证书、不切换微信账号。
- 本地真实生成带音轨视频：通过 HTTP/HTTPS 代理捕获、普通域名 TLS 隧道、完整下载/合并及解码均通过；HLS 清单重写下载通过；上游不受信任证书被拒绝。隔离注册表中代理恢复和其他应用修改冲突检查通过，候选不保存 Cookie/Authorization。
- 真实咖米课程、微信版本是否遵循系统代理、强制关闭窗口/断电的守护恢复尚未验证；只有完成用户笔记本测试后才能称为真实平台支持。当前咖米独立网站使用微信内 OAuth；分享页面已定位，但本机账号没有指定课程权限。
- .NET Framework 4.8 生成本机独立 CA，临时信任仅由软件内“开启”确认触发；退出尝试移除信任，留存私钥供本机复用。原代理先备份，冲突不覆盖。恢复入口和使用说明随包提供。

- 本机回环 HTTP 对照测试（不经过抓取代理）也曾偶发 ECONNRESET；未据此修改 Windows 网络/安全配置。已加入仅幂等 GET/HEAD 的有限重试，POST 不自动重试；无效上游证书仍拒绝。最终测试数量/云端结果见实际 Actions。

- 18 项本机回归通过，正式入口 --check 通过；拒绝“开启”会返回普通链接输入，未创建本机 Capture 配置、未安装证书或改系统代理。用户笔记本真实测试仍待进行。

## 0.4.0-alpha.3：课程名称和批量队列

2026-10-12 用户反馈：在笔记本开启抓取后，微信小程序的视频可识别并按编号下载；当前文件名为时间和地址摘要，编号操作不够明确。用户要求课程名保存和一系列课程的批量下载。

新增明确“输入数字”提示、范围/多编号/全部下载。已抓取的课程可以积累后一次顺序下载；失败继续下一节，全部跳过已成功项。文件按关联的课程标题保存，读不到时必填名称；支持命名更正；同名追加 (2) 不覆盖旧视频。只从限定课程响应/原文件名读取与媒体明确关联的名称，不按响应顺序猜课程，不读取登录/个人字段，不保存 JSON 全文。

若网站课程列表响应提供 8 节的名称及 MP4/HLS 地址，会一次生成候选；若只提供当前课媒体，8 节需分别打开开始播放，让软件抓到媒体后输入“全部”。不绕过权限枚举其他目录。实际咖米响应字段/缓存行为可能导致标题未自动读到，届时提示手工填写。新的真实名称与队列待笔记本测试，不能把用户旧单视频成功当作本版已验证。

用户补充要求去掉小鹅通回放文件名的中括号地址摘要：小鹅通路径也按原课程标题保存，保留标题中的日期，如《边缘循环》10.08.mp4；同名追加 (2)，不推断/伪造课程日期。已下载到用户笔记本的旧文件不被自动重命名。

验证：26 项本机平台/会话/抓取/命名队列回归和正式 EXE --check 通过；真实生成的带音轨 MP4 与 HLS 下载、合并和整段解码通过，压缩课程响应原样转发及同名并发保存保护通过。独立音频/片段不进入候选，防止播放分片挤掉课程列表。仅隔离证书/注册表测试，不激活开发电脑真实抓取。当前本机仍偶发回环连接 ECONNRESET，有限测试重试保留且不更改系统安全配置；真实新课程名和批量兼容仍待用户笔记本确认。
